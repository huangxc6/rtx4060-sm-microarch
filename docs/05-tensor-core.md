# Round 5：第 4 代 Tensor Core

数据来源：`results/20261115-214454-final/round5`（Round 0–5 同一次运行）。
方法见 `docs/00-methodology.md`。

## 0. 结论速览

| 精度 | PTX 形状 | SASS 指令 | 吞吐（FLOP/cycle/SM） | 折算 TFLOPS @2.75 GHz | 延迟 |
|---|---|---|---:|---:|---:|
| FP16 | `m16n8k16` | `HMMA.16816.F32` | **514** | **33.6** | 40.6 周期 |
| TF32 | `m16n8k8` | `HMMA.1688.F32.TF32` | **257** | **16.8** | 40.9 周期 |
| FP8 (e4m3) | `m16n8k32` | `QMMA.16832.F32.E4M3.E4M3` | **1022** | **66.9** | 38.8 周期 |

（三次独立运行的波动：FP16 513–514、TF32 257、FP8 1022–1031，差异 <1%。）

三条结论：

1. **吞吐严格正比于 K**：FP16 : TF32 : FP8 = 514 : 257 : 1022 ≈ 1 : 0.5 : 2，
   正好对应 k=16 : k=8 : k=32。说明三种精度用的是**同一条 MMA 流水线**，
   只是每次搬的 K 维不同——没有为低精度单独加宽。
2. **每调度器 128 FLOP/周期**（514 / 4）。一条 `HMMA.16816` 是 4096 FLOP，
   所以**每调度器每 32 周期退休一条 m16n8k16**。
3. **MMA 延迟 ≈ 40 周期**，三种精度几乎一样（38.8–40.9）。
   吞吐 32 周期 / 延迟 40 周期 ⟹ 每个调度器只要 2 条 MMA 在飞就能喂饱——
   这就是为什么 4 个 warp（每 warp 2 个独立累加器）就饱和了。

对比标量流水线：FP32 向量是 256 FLOP/cycle/SM（128 lane × 2），
所以 **FP16 张量是 FP32 的 2×，FP8 张量是 4×**。

## 1. 怎么测的

- 一条 MMA 是 **warp 级指令**，A/B 全部从寄存器取，**完全不碰显存**，
  因此测到的就是 Tensor Core 本身，不受 LSU 与缓存干扰。
- 一个 `m16n8k16` = 2·16·8·16 = **4096 FLOP**（整条 warp 合计，不是每线程）。
- 吞吐：每个 warp 用 **2 个独立累加器**交替发 MMA（避免依赖链），
  扫 warp 数 1/2/4/8 找饱和点。
- 延迟：单累加器依赖链（D 同时作为下一条的 C），32 条 MMA 除以 32。
- 三种精度各自独立编译，编译失败只跳过该精度。

### 这里踩了一个必须记下来的坑：不能数"所有指令"

初版按"函数内指令总数之差"归一，得到 FP16 = **768** FLOP/cycle/SM。
但把 SASS 拆开一看：

| | n=8 | n=64 | 增量 |
|---|---:|---:|---:|
| 指令总数 | 72 | 240 | 168 |
| 其中 `HMMA` | 16 | 128 | **112** |
| 其中杂项（MOV/LDG/…） | 56 | 112 | **56** |

**杂项条数也随迭代数增长**（每次迭代多 1 条）。源码里每次迭代是 2 条 MMA，
按总数归一等于把每 2 条 MMA 算成 3 条 ⟹ **FLOP 高估 1.5 倍**。

改成只数 `HMMA`/`QMMA` 之后：FP16 = 768 × 112/168 = **513**，
正好落在"每 SM 512 FLOP/周期"这个由规格书反推的值上。
FP8 更夸张（224 条总指令里只有 112 条是 `QMMA`，比例正好 2:1），
不修正的话会得到 2054 这种翻倍的值。

> **教训**：Round 2 用的"按 SASS 总条数归一"在这里不成立，
> 因为 MMA 的形状固定、但编译器会为它插入搬运指令。
> 计数必须精确到"哪一类指令"。

## 2. 与 warp 数的关系（饱和点）

| warp | FP16 | TF32 | FP8 |
|---:|---:|---:|---:|
| 1 | 129 | 64 | 257 |
| 2 | 256 | 128 | 515 |
| 4 | **514** | **257** | **1022** |
| 8 | 512 | 256 | 1024 |

前 3 级严格线性（每个新增 warp 多 128/64/257），**4 warp 就饱和**，8 warp 不再涨。

这与 Round 2 的 FFMA（4 warp 饱和）一致：**4 个调度器各带 1 个 warp 就打满了**。
区别在于 FFMA 是每个 warp 满速 1 条指令/周期，而 MMA 是每个 warp 每 32 周期一条。

这也说明为什么 1 warp 只有 129（= 513/4）：单个 warp 的 2 条 MMA 在飞，
不足以让一个调度器的流水线满速（需要 40/32 = 1.25 条在飞，2 条刚好够，但只有 1/4 的调度器在被用）。

## 3. wgmma 的负向验证

`wgmma` 是 Hopper（sm_90a）才有的 warpgroup 级 MMA。在 sm_89 上编译直接被拒：

```
ptxas application ptx input, line 30; error : Instruction 'wgmma.fence'
not supported on .target 'sm_89'
```

这是一条干净的负向结果：**这块卡的 Tensor Core 只能通过 `mma.sync`（warp 级）驱动，
没有 Hopper 的异步 warpgroup MMA 与 TMA 配套**。
换句话说，第 4 代 Tensor Core 的"新特性"里，FP8 有、wgmma/TMA 没有。

## 4. 没做到的

1. **稀疏（sparsity）MMA 没测**：`mma.sp.sync` 在 Ada 上支持（规格书的 2× 数字来自这里），
   但没有验证实际的 2× 是否成立。
2. **只有 m16n8kX 一种形状**：没测 m8n8k4、m16n8k4 等更小形状，也没测
   `mma.sync` 的 `.and`/`.xor` 变体。
3. **INT8 / INT4 张量**没测（`mma.sync` 的 s8/u8 变体）。
4. **MMA 与向量指令的并发**：MMA 占的是张量核，理论上可与 FFMA 同时发射；
   总发射率 4 IPC 的限制下两者会不会互抢发射槽，没测。
5. **多个 CTA 同时用张量核**时的聚合吞吐没测（本实验都是单 CTA 单 SM）。
6. **绝对 TFLOPS 与规格书的对照**：实测 FP16 33.6 TFLOPS，
   而公开资料常见的 4060 "FP16 Tensor" 数字（60.6 TFLOPS 一类）通常是带稀疏或按不同
   频率口径给的，两者不是同一口径，**不宜直接比较**。
