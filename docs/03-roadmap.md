## 优先 1：L2 的**容量**（延迟已被 Round 10 解决，容量还没有）

`docs/04-memory-hierarchy.md` 里 256 KiB–1 MiB 段两次运行差最多 35%，
导致 L2 的延迟与容量都给不出干净的数。

验证方案：

1. **独占 GPU**：停掉桌面合成（Windows 上可以切到不接显示器的会话，
   或用 `psexec -s` 在 session 0 跑），重跑 chase。
2. **每 SM 一条独立链**：单 warp 追逐对抢占极敏感。改成"每个 SM 上放一个 CTA、
   各跑一条独立链"，取**每 SM 的中位数**，能显著压低抢占影响（代价是失去单 SM 纯粹性）。
3. **更细的网格**：64 KiB 到 32 MiB 之间用 1 MiB 步进，判断是"台阶"还是"斜坡"。

## 优先 2：warp→调度器的定量映射（需要一个新方法）

Round 6 已经证明：≤8 warp 时所有 warp 同步启动 ⟹ 双峰是**共享调度器**造成的。
但**定量**不成立：per-warp 时间戳换算出的 IPC 之和（6 warp 时 4.51）
超过了实测的 4.00 IPC 硬上限，说明时间戳本身有随 warp 变化的系统偏差。

要定量，必须换掉"用时间戳推测"这条路：

1. **统计发射槽**：让每个 warp 在固定周期窗口里数自己执行了多少条指令
   （`asm` 计数 + 固定 `clock64` 窗口），而不是量总耗时。
2. **交叉校验**：用 `%globaltimer`（纳秒）与 `%clock64`（周期）同时采样，
   看偏差是否随 warp 变化——若是，就能解释 L29 的矛盾。
3. **利用已知硬上限**：4.00 IPC 是独立测出来的（Round 4.2），
   任何 per-warp 方案都必须让"各 warp IPC 之和 ≤ 4"，否则方法本身不成立。

## 优先 3：固定物理寄存器号（Round 8 已把范围收窄，但没定论）

Round 7 测到：FFMA 三源全不同时掉到 78 ops/cycle（可复用时的 0.62 倍）。
但**没能区分**两种机制：

- 读端口不足：每 lane 每周期供不起 3 次读，部分指令要 2 周期；
- bank 冲突：3 个源落在 2 个 bank 上必然有 2 个同 bank。

要分开，必须让三个源**确定性地**落在同 bank 或不同 bank。CUDA C++ 做不到（ptxas 自己分配），
可选路径：

1. **直接写 SASS**：用 `nvdisasm` 反汇编 → 手工改寄存器号 → 用 `cuModuleLoadData`
   直接加载改过的 cubin。这是最硬的办法，但要处理 ELF 与校验。
2. **PTX 命名寄存器**：`.reg .b32 %r<8>` 只保证 PTX 层面的编号，
   ptxas 仍会重映射——**实测不可行**，除非配合 `-maxrregcount` 反推。
3. **统计法**：生成大量随机的源寄存器组合，从 SASS 读出实际 bank 分布，
   用回归拟合"同 bank 对数 → 周期数"。不需要控制分配，只需要足够的样本。

路径 3 最现实：本工程的 harness 已经能从 SASS 里读寄存器号，只要批量生成变体即可。

## 优先 4：张量核剩下的部分

Round 5/6 已经测了 dense 的 FP16/TF32/FP8 和稀疏 FP16。剩下：

1. **稀疏的其它形状**：`m16n8k16` 稀疏（等效 dense k=8）、稀疏 TF32 / FP8。
2. **INT8 / INT4 张量**：`mma.sync` 的 s8/u8 变体。
3. **MMA 与向量指令的并发**：MMA 占张量核、FFMA 占 FP32 核。Round 4 已证明总发射
   卡在 4 IPC，所以两者会互抢发射槽——测混合流能否超过 4 IPC（预期不能）。
4. **多 CTA 聚合吞吐**：本工程所有张量实验都是单 CTA 单 SM。

## 其余

| 项 | 探针要点 |
|---|---|
| TLB 覆盖范围 | 固定工作集，改页内偏移分布，比较延迟 |
| `cp.async` / LDGSTS | 能否与计算重叠、能否绕过寄存器 |
| 常量内存 / 纹理路径 | `ld.const` / `ld.global.nc` 的延迟与吞吐 |
| 分支与发散代价 | 全 warp 一致分支 vs 32 路发散，测重收敛开销 |
| 原子操作 | `red.global.add` 的吞吐与 L2 侧延迟 |
| DPX 指令 | `viaddmax` 等视频指令的吞吐 |
| 共享内存峰值 32 字/周期 | 需要绕过 LSU 的 0.5 条/周期限制（例如用 `LDS.128` 一次搬 16 B/线程） |

## 附注：两个技术障碍

1. **LDS 地址空间转换**：CUDA C++ 里 `&smem[i]` 是通用地址，必须用
   `cvta.to.shared.u64` 转到 shared 窗口（Round 3 已解决）。
2. **`__shared__` 在 NVRTC 下可用**（关键字，不是头文件内容）；静态 smem ≤ 48 KiB。
